你大概率见过这样的发布会海报:一个新模型「在 MMMU 上拿下 XX 分,超越 GPT-X」。但 MMMU 是什么?这个分数怎么算出来的?为什么是 MMMU 而不是别的?换个 benchmark 它还排第一吗?

benchmark(基准测试) 就是把「这个 VLM(Vision-Language Model,能看图又能说话的模型)好不好」这种模糊感觉,压成一个可比较数字的尺子。而每家厂商会从一大堆分数里,挑一个最亮眼的当头版招牌——本教程把这个被反复强调的招牌分数,叫 北极星指标(North Star metric)。

这篇教程面向 VLM 小白,用 8 个螺旋结构章节(每节走「直觉 → 最小 demo → 正式化 → 真实代码引用 → 洞察」五步),系统讲透业界 VLM 评测的三层地图:

  • 通用能力(§3):跨学科智商测试,北极星是 MMMU。
  • 会读图会算(§4):文档 / 图表 / 数学,北极星常是 DocVQA/OCR。
  • 幻觉与诚实(§5):专门打假——高分≠真看懂。
  • grounding 定位(§6):从「答对文字」到「指对位置」。
  • 细节 / 瑕疵(§7):工业质检 / 画质,另一套完全不同的指标。

开头两节(§1 北极星框架、§2 评分地基)是全篇地基,最后一节(§8)收束成一张对照表 + 读榜 checklist。代码 verbatim 引自最常用的评测框架 open-compass/VLMEvalKit 与工业异常检测库 openvinotoolkit/anomalib。

1. 为什么需要 benchmark,以及什么是「北极星指标」

1.1 直觉

想象高考结束,有人问你考得怎么样。你大概率不会把六科分数一科一科报出来,而是说一句「我数学考了 145」——挑出最拿得出手的那一科,当成你的招牌。VLM(Vision-Language Model,视觉语言模型,即「能看图又能说话」的 AI)的世界也是一样:每个模型发布时,厂商会从一大堆评测分数里,挑一个最亮眼的数字放在头版海报上。这个被反复强调的招牌分数,我们就叫它北极星指标(North Star metric)——就像夜空里那颗最显眼、所有人都拿来定方向的星。

但要先有「分数」,才能有「招牌分数」。**benchmark(基准测试)**就是产生分数的那套考卷:一组固定的图 + 问题 + 标准答案,任何模型来做都用同一套题、同一种判分规则,于是「这个模型好不好」这种模糊感觉,被压缩成一个可以直接比较的数字。没有 benchmark,A 模型说自己「看图很准」,B 模型也说自己「看图很准」,谁也说服不了谁;有了 benchmark,大家在同一张考卷上见高下。

这些考卷不是只有一种。粗看下来,业界的 VLM benchmark 大致落在三层地图上:

  • 通用能力层:像跨学科综合卷,测模型整体「智商」(代表:MMMU、MMBench)。
  • grounding 定位层(grounding 指「把语言对应到图里的具体位置」):不只答对文字,还要框对、点对目标在哪(代表:RefCOCO、ScreenSpot)。
  • 细节 / 瑕疵层:专挑画面里的微小异常、缺陷(代表:工业质检类 MVTec-AD)。

三层各用不同的「尺子」(指标),不能混着比。把这些分数排成一张大表,按高低排名,就是你常在新闻里看到的 leaderboard(排行榜)——一种「谁是第一」的攀比文化。本节先不钻进任何一类考卷,只回答最朴素的问题:分数到底是怎么算出来的,以及为什么一个数字远远不够。

1.2 最小 demo

最简单的尺子叫 accuracy(准确率):答对的题数 ÷ 总题数。下面这段玩具代码,给一组模型预测和一组标准答案,直接算出准确率。

# 一份玩具评测:模型的预测 vs 标准答案
predictions = ["B", "A", "C", "B", "D"]   # 模型选的
answers     = ["B", "C", "C", "B", "A"]   # 标准答案

def accuracy(preds, gts):
    assert len(preds) == len(gts)
    correct = sum(p == g for p, g in zip(preds, gts))
    return correct / len(gts)

acc = accuracy(predictions, answers)
print(f"答对 {sum(p == g for p, g in zip(predictions, answers))} / {len(answers)} 题")
print(f"accuracy = {acc:.2%}")   # -> accuracy = 60.00%

五道题对了三道,准确率 60%。逻辑朴素到一句话能说完:逐题比对,数对的,再除以总数。真实 benchmark 的判分内核就是这个,只是外面包了一层层「怎么判两个答案算相等」的麻烦——这正是后面几节要拆的。

1.3 正式化

把上面的玩具放大成可信的评测,需要四个要素缺一不可,我们叫它评测四要素:

  • 数据集(dataset):固定的图 + 问题 + 标准答案集合,所有模型考同一套。
  • 任务格式(task format):答案长什么样——单选(ABCD)、是非(yes/no)、还是开放式文字。
  • 指标(metric):把「预测」和「答案」映射成分数的函数,比如 accuracy。
  • 协议(protocol):怎么喂题、怎么从模型回答里抠出最终答案、用哪个数据划分(split)——这层最容易被忽视,却决定了分数能不能横向比较。

最基础的指标 accuracy 形式化如下:

\[\text{accuracy} = \frac{1}{N}\sum_{i=1}^{N} \mathbb{1}\big[\hat{y}_i = y_i\big]\]

—— 翻译:把 \(N\) 道题逐题判断「模型预测 \(\hat{y}_i\) 是否等于标准答案 \(y_i\)」,相等记 1 不等记 0(这就是指示函数 \(\mathbb{1}[\cdot]\) 的含义),求和再除以题数,得到答对的比例。

公式里藏着一个魔鬼:\(\hat{y}_i = y_i\) 这个「相等」到底怎么判?当答案是干净的 ABCD,相等就是字符串相等;但模型实际会回「我觉得应该选 B,因为图里…」,你得先把 B 从一段话里抠出来。能抠出答案的题占比,要求满足 \(i \lt N\) 时每一项都成立,否则分数就失真。所以协议和指标同样重要:同一份数据、同一个 accuracy 公式,换一种答案提取协议,分数能差出一大截。这也是为什么不同来源报的「同一个模型在同一 benchmark 上」的分数,有时对不上。

1.4 代码引用

工程上还有一个细节:一个 benchmark 跑完,往往同时产出好几个数字(分维度的、分 split 的、总分…)。那「北极星」——也就是该填进 leaderboard、该上海报的那个主指标(primary metric)——是怎么自动选出来的?VLMEvalKit 的做法是给每个候选指标名打分,取分最高的那个:

sources/repos/open-compass-VLMEvalKit/vlmeval/dataset/image_base.py:L17-L51 — VLMEvalKit 如何从一堆指标里自动挑出主指标

def _choose_primary_metric_key(metrics: dict[str, Any]) -> str | None:
    if not metrics:
        return None

    scored = []
    for key in metrics:
        lower_key = str(key).lower()
        score = 0
        if lower_key == 'overall':
            score = 100
        elif lower_key.endswith('|overall'):
            score = 95
        elif 'overall' in lower_key:
            score = 90
        elif lower_key == 'acc' or lower_key.endswith('|acc'):
            score = 80
        elif 'acc' in lower_key:
            score = 70
        elif lower_key == 'score' or lower_key.endswith('|score'):
            score = 60
        elif 'score' in lower_key:
            score = 50

        if 'split=test' in lower_key:
            score += 4
        elif 'split=validation' in lower_key:
            score += 3
        elif 'split=val' in lower_key:
            score += 2
        elif 'split=dev' in lower_key:
            score += 1
        scored.append((score, str(key)))

    scored.sort(key=lambda item: (-item[0], item[1]))
    return scored[0][1]

对照 §1.3 的概念:这段代码就是「从一组指标里钦定北极星」的程序化版本。优先级清清楚楚——Overall(总分,100 分)优于 Acc(准确率,80 分)优于 Score(泛化分数,50 分),也就是 Overall 优于 Acc 优于 Score 的打分逻辑;名字越接近这些关键词,得分越高(完全等于 'overall' 给 100,只是包含 overall 给 90)。最后那几行 split=test/validation/val/dev 的小幅加分(+4/+3/+2/+1),对应的正是 §1.3 说的「协议里的 split 选择」:同样是总分,测试集(test)上的比开发集(dev)上的更可信,于是优先当北极星。一句话:_choose_primary_metric_key 把「该把哪个数字放上海报」这件本来很主观的事,固化成了一套可复现的排序规则。

1.5 洞察

  • 北极星指标是「营销」和「真实能力」的混合体:它确实反映模型某方面强,但也是厂商精心挑出来最好看的那个数字——招牌科目不等于全科水平。
  • 单一数字天然危险:一个分数会把模型在其他维度的短板(幻觉、定位、细节)全部隐藏,高分常常只意味着「擅长这一类题」,而非「真的看懂了图」。
  • 要看一整组,而不是一个分数:三层地图各有各的尺子,只有把通用能力 / grounding 定位 / 细节瑕疵的分数摆在一起看,才能判断一个模型是真全面,还是只在自家北极星那一科上偏科。

2. 评分的地基:多选题、答案提取与 Circular Eval

上一节我们说,benchmark 的本质是把"模型好不好"压成一个可比较的数字。但这个数字到底怎么算出来?这一节我们就钻进去看「分数的地基」——它比你想的要脏得多。后面 §3(MMMU/MMBench)和 §5(POPE/MMStar)的所有分数,都建立在这一节讲的两件事上:答案提取和 Circular Eval。

2.1 直觉

绝大多数 VLM benchmark 长得像高考选择题:给一张图、一个问题,外加 A/B/C/D 四个选项,标准答案是其中一个字母。你可能以为判分超简单——对比一下字母就行了。问题在于:模型根本不会乖乖只答一个「B」。

你问它"图里的动物是什么?(A)猫 (B)狗 (C)兔子 (D)鸟",它很可能回一大段:"从图中蓬松的毛发和竖起的耳朵来看,我认为最合理的答案应该是 B,也就是狗。"标准答案存的是字母 B,模型吐的是一整段啰嗦的话。判分前必须先从这段自由文本里把它真正选的那个选项抠出来——这个步骤就叫答案提取(answer extraction)。

打个比方:你是改卷老师,标准答案卡上写着「B」,但学生没在答题卡涂卡,而是在卷子上写了一篇小作文,你得先从作文里读出他到底选了哪个,才能对答案。这个"读出选项"的环节,就是整条评分流水线里最容易出错、却最常被忽略的一环。

提取出选项之后,剩下的事才是大家想象中的"判分":提取到的选项 == 标准答案就记 1 分(命中,hit),否则 0 分,最后求平均得到准确率(accuracy)。所以一道选择题的真实流程是两段:先提取、再比对。难点几乎全在第一段。

2.2 最小 demo

先用最朴素的方式做一遍:用正则从一段啰嗦回答里抠出 ABCD,再和标准答案比对算 accuracy。

import re

# 模型对每道题的自由文本回答
preds = [
    "从图中特征看,我认为答案应该是 B,也就是狗。",
    "The answer is (C).",
    "这道题我选 a 选项。",
    "我不太确定,可能是只鸟吧。",   # 没给字母,提取失败
]
golds = ["B", "C", "A", "D"]      # 标准答案

def extract(s):
    s = s.upper()
    m = re.search(r"[ABCD]", s)   # 抓第一个出现的选项字母
    return m.group(0) if m else ""

hits = []
for pred, gold in zip(preds, golds):
    choice = extract(pred)
    hits.append(1 if choice == gold else 0)   # 命中记 1,否则 0
    print(f"抠出={choice or '∅':2}  标准={gold}  {'✓' if hits[-1] else '✗'}")

accuracy = sum(hits) / len(hits)
print(f"accuracy = {accuracy:.2%}")           # = 75.00%

前 3 题都能抠出字母并答对,第 4 题模型没给字母、正则抓空,直接判错——哪怕它语义上其实答对了"鸟"。这就暴露了核心矛盾:提取器的能力直接决定分数。一个太笨的正则会把"语义对、格式不对"的回答误判成错。真实的 harness(评测框架)正是在这个朴素正则之上,叠了一层层补丁来救场。

2.3 正式化

把上面的玩具流程写成统一形式。设第 \(i\) 道题模型的原始回答是 \(r_i\),标准答案是 \(g_i\),提取器是函数 \(\mathrm{Ext}(\cdot)\),共 \(N\) 道题。命中指示量与准确率定义为:

\[h_i = \mathbb{1}\!\left[\mathrm{Ext}(r_i) = g_i\right], \qquad \mathrm{Acc} = \frac{1}{N}\sum_{i=1}^{N} h_i\]

—— 翻译:第 \(i\) 题提取出的选项若等于标准答案,\(h_i\) 记 1 否则记 0;准确率就是所有题命中量 \(h_i\) 的平均值。

关键在于 \(\mathrm{Ext}\) 有两种实现路线。一是 exact-match 提取:纯规则,用正则和关键词("The answer is …")硬抠字母,快、免费、可复现,但碰到格式古怪的回答就抓瞎(像 demo 第 4 题)。二是 LLM-judge 提取:当规则抠不出时,把"题目+选项+模型回答"丢给另一个大模型,让它判断"这段话语义上选了哪个",更鲁棒但更慢、要花钱、还可能引入裁判模型自己的偏好。VLMEvalKit 采用的正是"先规则、抠不出再退而求其次"的混合策略。

但即便提取完美,普通 accuracy(下文叫 vanilla,即只问一遍)还有个大漏洞:位置偏好。模型可能有"无脑选 B"的偏置,或纯靠运气蒙中一道四选一(期望 25% 白送)。MMBench 提出的 CircularEval(循环评估) 就是来堵这个漏洞的:把同一道题的 \(N\) 个选项循环移位 \(N\) 次,每次都让选项顺序不同(正确答案分别落在第 1、2、…、\(N\) 位),问 \(N\) 遍;只有 \(N\) 遍全答对,这道题才算对。

设第 \(i\) 题循环到第 \(k\) 个版本时的命中量为 \(h_i^{(k)}\),则该题的 circular 命中与整卷 circular 准确率为:

\[c_i = \prod_{k=1}^{N} h_i^{(k)}, \qquad \mathrm{Acc}_{\text{circ}} = \frac{1}{M}\sum_{i=1}^{M} c_i\]

—— 翻译:一道题要把 \(N\) 个移位版本全部答对(\(N\) 个 \(h\) 连乘,只要有一个为 0,\(c_i\) 就为 0),才算这题命中;整卷 circular 准确率是 \(M\) 道题里这种"全对题"的占比。

因为连乘里只要错一个就归零,\(\mathrm{Acc}_{\text{circ}}\) 必然不高于 vanilla accuracy——实践中 circular 分数通常比 vanilla 低若干个点(具体差多少视模型而定)。落差越大,说明模型越依赖蒙和位置偏好。

2.4 代码引用

来看 VLMEvalKit 真实的两段实现,分别对应 §2.3 的 \(\mathrm{Ext}\)(提取器)和 \(\mathrm{Acc}\)(求 hit 均值)。

sources/repos/open-compass-VLMEvalKit/vlmeval/dataset/utils/multiple_choice.py:L585-L612 — 从模型自由文本里正则抠出 ABCDE 选项的答案提取器

def extract_characters_regex(s, choices=['(A)', '(B)', '(C)', '(D)', '(E)']):
    if type(s) is dict:
        s = ''
    s = s.strip()
    answer_prefixes = [
        'The best answer is',
        'The correct answer is',
        'The answer is',
        'The answer',
        'The best option is'
        'The correct option is',
        'Best answer:'
        'Best option:',
    ]
    for answer_prefix in answer_prefixes:
        s = s.replace(answer_prefix, '')

    if len(s.split()) > 10 and not re.search('[ABCDE]', s):
        return ''
    matches = re.search(r'[ABCDE]', s)
    if matches is None:
        for choice in choices:
            if s.lower() in choice.lower():
                return choice[1]
        return ''
    return matches[0]

对照 §2.3 的 \(\mathrm{Ext}\):这就是 exact-match 提取器的工业版,比我们 demo 的一行正则讲究得多。它先把"The answer is …"之类的套话前缀删掉(免得正则抓到前缀里的字母),再做一道关键判断——如果回答超过 10 个词却完全找不到 ABCDE,就直接返回空串放弃(对应 demo 第 4 题那种长篇大论又不给字母的情况);否则用 re.search('[ABCDE]') 抠出第一个选项字母。抠不到字母时还有个兜底:看回答是否就是某个选项的文字本身(比如直接答"狗"),命中则返回对应字母。这一整套规则失效时,上层才会调用 LLM-judge 来救。

        df['split'] = ['none'] * len(df)
        res['split'] = ['none']

    for group in [None, 'l2-category', 'category']:
        if group is None:
            res['Overall'] = [np.mean(df[df['split'] == sp]['hit']) for sp in res['split']]
        elif group not in df:
            continue
        else:
            abilities = list(set(df[group]))
            abilities.sort()
            for ab in abilities:
                ab_name = MMB_abbrs[ab] if ab in MMB_abbrs else ab
                sub_df = df[df[group] == ab]
                res[ab_name] = [np.mean(sub_df[sub_df['split'] == sp]['hit']) for sp in res['split']]
    return pd.DataFrame(res)

对照 §2.3 的 \(\mathrm{Acc}=\frac{1}{N}\sum h_i\):每道题的命中量已经事先算好存进 DataFrame 的 hit 列(circular 题这里的 hit 就是 §2.3 那个连乘 \(c_i\)),report_acc 做的就是对 hit 列求 np.mean——这正是"命中量的平均=准确率"的公式落地。它还顺手按 category / l2-category 这些能力维度分组各求一次均值,所以 MMBench 不只给一个总分(Overall),还能给出每个能力维度的细分准确率,这正是 §3 要展开的"能力维度细分"。

2.5 洞察

  • circular 更难被蒙,是因为它同时掐死了"位置偏好"和"瞎猜"。 四选一靠运气能蒙中 25%,但要把 4 个移位版本全部蒙对,概率掉到 \(0.25^4\)(不到 0.4%);"无脑选 B"的偏置在选项轮转后也会立刻露馅。所以 vanilla 和 circular 的分差,本身就是一把"模型有多虚"的尺子。
  • 提取器本身是误差源,它让不同 harness 的分数不可直接比。 同一个模型、同一套题,换一个提取规则或换一个 LLM-judge,分数就会浮动。看到两份榜单分数不一样,先别急着下结论"模型变强了"——很可能只是它们用了不同的 \(\mathrm{Ext}\)。
  • accuracy 看似简单,其实暗藏协议差异。 "0.85 的准确率"背后,藏着"是不是 circular、提取器是规则还是 LLM、抠不出算错还是重试"等一串没写在表头的约定。读分数前先问清楚协议,是这一节最该带走的习惯——这也是 §3、§5 一切分数能不能横向比较的前提。

3. 通用能力综合卷:MMMU / MMBench / MME / SEED-Bench

如果只能用一个分数告诉别人「这个 VLM 到底聪不聪明」,大多数厂商会选这一类卷子。它们不挑某个具体技能(看图表、识文字、定位),而是想衡量「综合智力」。本节的北极星(沿用 §1 的 north star 概念)毫无悬念地落在 MMMU 上。

3.1 直觉

把这四份卷子想象成给模型设计的几套不同风格的「智力测验」:

  • MMMU = 大学跨学科高考难卷。它收了 11.5K 道大学级别的题,横跨 6 大学科(艺术设计、商业、科学、健康医学、人文社科、技术工程),细到 30 个科目、183 个子领域,图像类型也有 30 种(图表、乐谱、化学结构式……)。这不是「看图说话」,而是「看着专业图表用专业知识做推理」。难到什么程度?发布当时(2023),连 GPT-4V 也只有约 56%、Gemini Ultra 约 59%——离满分远得很。正因为它够难、够「专家级」,它成了事实上的通用能力北极星。
  • MMBench = 按能力维度细分的双语模拟卷。它是中英双语,把能力拆成一棵细分维度树(粗粒度感知、细粒度推理等),并且用 §2 讲过的 CircularEval(把选项循环移位、几次全对才算真的对)来防蒙。
  • SEED-Bench = 多维度多选题题库。大规模多选题,覆盖 12 个评测维度,从单图理解到时序推理都有,胜在维度全、题量大。
  • MME = 感知 + 认知双卷,且只考判断题。它把能力分成 perception(感知,10 类)和 cognition/reasoning(认知,4 类)共 14 个子任务,每张图问两个 yes/no(一正一反),用一套自定义的计分把结果压成分数。

为什么头版偏偏是 MMMU?因为它最贴近「expert AGI(专家级通用智能)」的叙事——一道题往往需要既看懂专业图,又调用大学课本知识做多步推理,这恰好是厂商发布会最想证明的东西。

先用一个玩具脚本感受 MMMU 风格的评测:每题是带图的多选题,我们沿用 §2 的 hit(命中)定义,并按学科分组求 accuracy(命中均值)。

3.3 正式化

MMMU / MMBench / SEED-Bench 的主指标(primary metric)都是 §2 定义的 accuracy:对一组 \(N\) 道题,

\[\text{accuracy} = \frac{1}{N}\sum_{i=1}^{N} \text{hit}_i, \qquad \text{hit}_i \in \{0,1\}\]

—— 翻译:把每题是否命中(0 或 1)取平均,就是准确率;MMBench 的 hit 还要叠加 CircularEval(几次移位全对才记 1),SEED 则在 12 个维度上分别这样算再汇总。

MME 的计分要单独说,因为它没用裸 accuracy。每张图配两道 yes/no(一正一反),对某一类别(category)\(c\) 定义两个量:

\[\text{acc}_c = \Big(\tfrac{1}{2M_c}\textstyle\sum_{j=1}^{M_c}(y_{j}^{+}+y_{j}^{-})\Big)\times 100, \qquad \text{acc\_plus}_c = \Big(\tfrac{1}{M_c}\textstyle\sum_{j=1}^{M_c} y_{j}^{+}\,y_{j}^{-}\Big)\times 100\]

—— 翻译:\(M_c\) 是该类别的图数,\(y^{+},y^{-}\) 是同一图正/反两问是否答对(0/1);acc 是「单题正确率×100」,acc_plus 是「一图两问都对(乘积为 1)才记分×100」,后者比前者严苛得多。

每个类别的得分把这两项相加,满分 200:

\[\text{score}_c = \text{acc}_c + \text{acc\_plus}_c, \qquad \text{score}_c \in [0, 200]\]

—— 翻译:单题对最多贡献 100,两问全对再额外贡献 100,所以一个类别封顶 200 分;这正是 MME「每类满分 200」的由来。

最后把类别按 perception / cognition 两组分别求和得到总分:

\[S_{\text{perc}} = \sum_{c\,\in\,\text{perception}} \text{score}_c, \quad S_{\text{cog}} = \sum_{c\,\in\,\text{cognition}} \text{score}_c, \quad S_{\text{total}} = S_{\text{perc}} + S_{\text{cog}}\]

—— 翻译:感知 10 类求和上限 \(10\times200=2000\),认知 4 类求和上限 \(4\times200=800\),两者相加得到 MME 著名的总分上限 2800;因为量纲是自创的,它很难和别的 benchmark 直接横比。

3.5 洞察

  • MME 的 2800 是「自定义量纲」,天生难横比。它把 yes/no 双问、两个 acc 相加、再跨类别求和,得到一个只在 MME 内部有意义的数字。一个模型 MME 拿 1800 分,你无法直接换算成 MMMU 的百分比——跨 benchmark 比较时务必各回各家的尺子,别把 2800 制和百分制混在一张图里。
  • MMMU 成为事实北极星,是「难度 + 跨学科 + 叙事」三者共振的结果。它够难(发布当时顶尖模型也只五六成)、覆盖面够专业(6 学科 30 图种)、又恰好贴合厂商想讲的「专家级通用智能」故事,于是发布会头版几乎必放 MMMU。
  • 综合卷高分 ≠ 会定位、会看细节。这一类卷子考的是「跨学科知识 + 推理」,但它基本不考「把目标框在哪、像素级的微小瑕疵」。一个 MMMU 很高的模型,完全可能在 grounding 定位(§6)和细节/瑕疵识别(§7)上摔得很惨——这正是后面两节要拆穿的盲区。

4. 会读图会算:VQA 家族与 MathVista

到这一节,我们已经会判多选题了(§2 的答案提取 + exact-match)。但真实世界里,很多看图问题没有 ABCD 选项,模型得直接说出答案:"这张图表里销量最高的月份是几月?""这张发票的总金额是多少?""这个公式的结果是?"这类开放式回答(open-ended)的判分,比多选题棘手得多——本节就讲清楚 VQA(Visual Question Answering)家族怎么把"看图回答"变成一个可比较的数字,以及为什么 ChartQA、DocVQA 各自发明了不同的"宽容"指标。

4.1 直觉

设想一道图表题,标准答案(gt)是 5%,模型答了 5.0%。按 §2 那种死板的 exact-match,字符串不相等,判错。可这明明是对的——只是写法不同。再设想一道文档题,答案是 Microsoft,模型 OCR 时手抖输出了 Micrsoft,少一个 o。exact-match 又判错——但任何人都看得出模型其实读对了,只是拼写差一个字母。

问题出在哪?开放式回答的"对"是有容差的,而 exact-match 没有容差。如果硬用 exact-match,我们会系统性地冤枉模型,算出来的 accuracy(§1 定义的命中均值)严重偏低,这个数字就失去了意义。

于是 VQA 家族针对两类典型场景,各发明了一种"宽容"指标:

  • relaxed accuracy(ChartQA, arxiv 2203.10244):针对图表里的数值答案。只要预测值和标准值的相对误差在 5% 以内,就算命中(hit);但非数值答案仍然要求精确匹配。这样 5% 和 5.0%、0.0498 和 0.05 都能算对,而文字类答案不松口。
  • ANLS(DocVQA, arxiv 2007.00398):全称 Average Normalized Levenshtein Similarity,即"平均归一化编辑距离相似度"。针对文档图像里的文字答案,用编辑距离衡量 Micrsoft 和 Microsoft 有多接近,从而容忍 OCR 带来的小拼写差。DocVQA 上人类水平约 94.36%,可见这任务本身就允许细微出入。

另外还有几个本节的常客:TextVQA(arxiv 1904.08920,读图中文字回答)、AI2D(arxiv 1603.07396,科学示意图多选理解)。而 MathVista(arxiv 2310.02255)更进一步——它把数学推理叠加到看图上:6,141 道题,要求模型既看懂图(图表、几何图、函数曲线),又算对数。发布当时(2023)GPT-4V 约 49.9%,人类约 60.3%,差距明显,说明"会读图"和"会算"叠在一起时,模型仍力不从心。

4.2 最小 demo

先用 30 行 python 把 relaxed accuracy 的核心逻辑跑通,把上面的直觉落成可执行代码:数值答案走 5% 相对误差容差,非数值答案退回精确匹配。

def to_float(text):
    text = text.strip()
    try:
        if text.endswith("%"):            # "5%" -> 0.05,百分号统一成小数
            return float(text.rstrip("%")) / 100.0
        return float(text)
    except ValueError:
        return None                       # 非数值,返回 None

def relaxed_hit(pred, gt, tol=0.05):
    p, g = to_float(pred), to_float(gt)
    if p is not None and g is not None and g != 0:
        return abs(p - g) / abs(g) <= tol     # 数值:相对误差 <= 5%
    return pred.strip().lower() == gt.strip().lower()  # 非数值:精确匹配

samples = [("5.0%", "5%"), ("0.0498", "0.05"),
           ("Microsoft", "Micrsoft"), ("March", "March")]
hits = [relaxed_hit(p, g) for p, g in samples]
print(hits)                               # [True, True, False, True]
print("relaxed accuracy =", sum(hits) / len(hits))  # 0.75

注意第三个样本:Microsoft vs Micrsoft 是文字答案,relaxed accuracy 对它毫不留情,判 False。这正是 relaxed accuracy 的盲区——它只对数值宽容。要救这种 OCR 拼写差,得换 ANLS,见 4.3。

4.3 正式化

relaxed correctness(数值容差)。设预测值 \(p\)、标准答案 \(g\)(\(g \neq 0\)),容差阈值 \(\tau = 0.05\)。判定命中的条件是:

\[\text{hit}(p, g) = \mathbb{1}\!\left[\frac{\lvert p - g \rvert}{\lvert g \rvert} \le \tau\right]\]

—— 翻译:预测与标准答案的相对误差不超过 5% 就算命中(\(\mathbb{1}[\cdot]\) 是指示函数,条件成立取 1 否则取 0);若答案不是数值,则退回 §2 的 exact-match。

ANLS(归一化编辑距离相似度)。设 \(\text{lev}(a, b)\) 为字符串 \(a, b\) 的 Levenshtein 编辑距离(最少插入/删除/替换次数),则单题相似度为:

\[\text{NLS}(p, g) = 1 - \frac{\text{lev}(p, g)}{\max(\lvert p \rvert,\, \lvert g \rvert)}\]

—— 翻译:编辑距离除以两串中较长者的长度得到"差异比例",用 1 减去它就是"相似比例",完全相同时为 1,毫不相干时趋近 0。

ANLS 还有一道阈值门:相似度低于阈值 \(\theta\)(DocVQA 取 0.5)时直接记 0,不给"半对"的分:

\[\text{score}(p, g) = \begin{cases} \text{NLS}(p, g), & \text{NLS}(p, g) \ge \theta \\ 0, & \text{NLS}(p, g) \lt \theta \end{cases}\]

—— 翻译:相似度够高(达到 0.5)才按相似度给分,差得太远就当全错,避免给"蒙对一半字符"的答案虚高的分数。最终的 ANLS 是全部测试题 \(\text{score}\) 的均值(这正是名字里 Average 的来历,也就是 §1 的命中均值在容差版本下的推广)。

def relaxed_correctness(target: str,
                        prediction: str,
                        max_relative_change: float = 0.05) -> bool:
    """Calculates relaxed correctness.

    The correctness tolerates certain error ratio defined by max_relative_change.
    See https://arxiv.org/pdf/2203.10244.pdf, end of section 5.1:
    “Following Methani et al. (2020), we use a relaxed accuracy measure for the
    numeric answers to allow a minor inaccuracy that may result from the automatic
    data extraction process. We consider an answer to be correct if it is within
    5% of the gold answer. For non-numeric answers, we still need an exact match
    to consider an answer to be correct.”

    Args:
      target: Target string.
      prediction: Predicted string.
      max_relative_change: Maximum relative change.

    Returns:
      Whether the prediction was correct given the specified tolerance.
    """

    def _to_float(text: str) -> Optional[float]:
        try:
            if text.endswith('%'):
                # Convert percentages to floats.
                return float(text.rstrip('%')) / 100.0
            else:
                return float(text)
        except ValueError:
            return None
    prediction = str(prediction)
    target = str(target)
    prediction_float = _to_float(prediction)
    target_float = _to_float(target)
    if prediction_float is not None and target_float:
        relative_change = abs(prediction_float - target_float) / abs(target_float)
        return relative_change <= max_relative_change
    else:
        return prediction.lower() == target.lower()

对照 4.3 公式:_to_float 把 5% 这样的字符串归一成小数,正是 4.2 demo 里那一步;relative_change <= max_relative_change 一行就是 relaxed correctness 公式 \(\lvert p-g\rvert / \lvert g\rvert \le \tau\);else 分支的 prediction.lower() == target.lower() 就是非数值时退回 exact-match。注意 if prediction_float is not None and target_float: 这个判断隐含了 \(g \neq 0\)(因为 0.0 在布尔上下文里为假),刚好对应公式里 \(g \neq 0\) 的前提。

再看 DocVQA 的 ANLS,它拆成两个函数:编辑距离 + 距离比例计算。

sources/repos/open-compass-VLMEvalKit/vlmeval/dataset/utils/vqa_eval.py:L217-L240 — DocVQA 的 ANLS:用归一化编辑距离容忍 OCR 小拼写差异

def levenshtein_distance(s1, s2):
    if len(s1) > len(s2):
        s1, s2 = s2, s1

    distances = range(len(s1) + 1)
    for i2, c2 in enumerate(s2):
        distances_ = [i2 + 1]
        for i1, c1 in enumerate(s1):
            if c1 == c2:
                distances_.append(distances[i1])
            else:
                distances_.append(1 + min((distances[i1], distances[i1 + 1], distances_[-1])))
        distances = distances_
    return distances[-1]


def anls_compute(groundtruth, prediction):
    gt_answer = ' '.join(groundtruth.strip().lower().split())
    det_answer = ' '.join(prediction.strip().lower().split())
    dist = levenshtein_distance(gt_answer, det_answer)
    length = max(len(groundtruth.upper()), len(prediction.upper()))
    values = 0.0 if length == 0 else float(dist) / float(length)
    return values

对照 4.3 公式:levenshtein_distance 是标准的动态规划编辑距离,对应公式里的 \(\text{lev}(p, g)\);anls_compute 先做大小写归一与空白折叠(strip().lower().split()),再算 dist / length,其中 length = max(...) 就是公式分母 \(\max(\lvert p\rvert, \lvert g\rvert)\)。

关键一点别看错:anls_compute 返回的 values 是距离比例(\(\text{lev}/\max\)),也就是公式里 NLS 表达式中被 1 减掉的那一项,而不是 ANLS 分数本身。真正的相似度是 \(1 - \text{values}\),而最终的 ANLS 分数还要再过一道阈值门:\(1 - \text{values} \lt 0.5\) 时整题记 0。换句话说,这个函数只算了一半,调用方拿到 values 后还得做 1 - values 并卡阈值,才是 4.3 里完整的 \(\text{score}(p, g)\)。看代码时若把 anls_compute 的返回值当成 ANLS 分数,就会把高分低分彻底读反。

4.5 洞察

  • 指标选错 = 分数没意义。对数值题硬套 exact-match,会因为 5% ≠ 5.0% 这种纯格式差异系统性地冤枉模型,算出来的 accuracy 低得离谱却毫无诊断价值。relaxed accuracy 和 ANLS 的存在,本质是承认"开放式回答的对错有容差"——选对指标,数字才对得上人类直觉。
  • OCR / 文档是很多商用 VLM 的真北极星。DocVQA、ChartQA、TextVQA 这类任务直接对应发票识别、报表解析、合同抽取等落地场景,商业价值极高。所以厂商发布商用模型时,往往把 DocVQA/OCR 类分数放在头版当北极星指标——它不是炫技,而是真金白银的能力凭证。
  • "容差"设计背后是工程现实。relaxed accuracy 的 5% 来自图表数据自动抽取的固有噪声,ANLS 的编辑距离来自 OCR 的拼写抖动——两者都是在"判分要严谨"和"别被无关的表层差异淹没真实能力"之间做工程折中。再叠上 MathVista 把数学推理压到看图之上(发布当时 GPT-4V 49.9% vs 人类 60.3%),你会发现:VQA 家族的判分演化,始终在追问同一个问题——怎样让一个数字,既公平又有区分度。

5. 幻觉与「视觉到底有没有用」:POPE / HallusionBench / MMStar

前面几节我们一直在教模型「怎么拿高分」,这一节反过来——专门打假。它没有单一的「北极星指标」,因为它的使命恰恰是揭穿别的北极星:榜单高分,不等于模型真的看懂了图。这是小白最该记住的一课。

5.1 直觉

设想一场开卷考试。你以为考的是「读材料的能力」,结果发现两个尴尬真相。

第一个尴尬:考生会一本正经地胡说八道。 你给一张只有猫的照片,问模型「图里有狗吗?」,它信誓旦旦地回答「有,一只棕色的狗趴在猫旁边」——图里根本没有狗。这就是物体幻觉(object hallucination):模型把不存在的东西描述得活灵活现。POPE 这个 benchmark 就是专门抓这种瞎编:它问一大堆「图里有没有 X?」的 yes/no 题,其中一半的 X 真实存在、一半根本不存在,看模型会不会把「没有」答成「有」。

第二个尴尬:很多「看图题」其实盖住图也能蒙对。 就像有些高考题,你不用读阅读材料,光凭常识和选项排除法就能选对答案——那这道题还测得出「阅读能力」吗?MMStar 论文实测发现:把图整个盖住、只给模型问题和选项,GeminiPro 在 MMMU 上居然还能答对 42.9%。这说明很多题存在视觉冗余(visual redundancy):视觉信息根本不必要。更糟的是数据泄漏(leakage):模型在训练时背过了测试题,等于考试前偷看了答案。

HallusionBench 把这两件事揉在一起做得更刁钻:它人工精心构造了 346 张图、1129 个问题,故意纠缠「语言幻觉」(模型不看图、凭语言先验下结论,比如「冰是冷的」)和「视觉错觉」(模型看了图却被误导)。结果有多惨?发布当时(2023),即便是 GPT-4V,它的 question-pair(配对)准确率也只有约 31%。这个极低的数字告诉我们:在「会不会被幻觉和错觉骗」这件事上,当年最强的模型也几乎是瞎蒙。

5.2 最小 demo

先用一个玩具版的 POPE 式 probing,把「抓幻觉」这件事跑通。我们准备几道 yes/no 题,有真有假,然后把模型回答当成二分类来算 precision / recall / F1。

# 玩具版 POPE：yes/no probing 抓物体幻觉
# 约定：Yes=1（说"图里有 X"），No=0（说"图里没有 X"）
gold = ["Yes", "No", "No", "Yes", "No", "Yes"]   # 标准答案：X 是否真实存在
pred = ["Yes", "Yes", "No", "Yes", "Yes", "No"]  # 模型回答（两个把"没有"答成"有"=幻觉）

def f1_report(gold, pred):
    y_true = [1 if g == "Yes" else 0 for g in gold]
    y_pred = [1 if p == "Yes" else 0 for p in pred]
    tp = sum(t == 1 and p == 1 for t, p in zip(y_true, y_pred))  # 真有，且答有
    fp = sum(t == 0 and p == 1 for t, p in zip(y_true, y_pred))  # 真没有，却答有 = 幻觉
    fn = sum(t == 1 and p == 0 for t, p in zip(y_true, y_pred))  # 真有，却答没有
    precision = tp / (tp + fp) if tp + fp else 0
    recall    = tp / (tp + fn) if tp + fn else 0
    f1 = 2 * precision * recall / (precision + recall) if precision + recall else 0
    acc = sum(t == p for t, p in zip(y_true, y_pred)) / len(y_true)
    return precision, recall, f1, acc

p, r, f1, acc = f1_report(gold, pred)
print(f"precision={p:.2f} recall={r:.2f} F1={f1:.2f} acc={acc:.2f}")
# 输出: precision=0.50 recall=1.00 F1=0.67 acc=0.67

注意那两个 fp:模型把「没有」答成「有」,这正是幻觉。它们把 precision 拉到了 0.5。如果只看 accuracy(0.67)感觉还行,但 F1 立刻暴露出「这模型爱瞎说有」的毛病——这就是下面要正式化的核心。

5.3 正式化

POPE 把每道 yes/no 题当成一个二分类问题:「图里有 X」记为正类(1),「图里没有 X」记为负类(0)。对照模型预测和标准答案,得到三个计数:TP(真有且答有)、FP(真没有却答有)、FN(真有却答没有)。在此之上定义两个指标:

\[precision=\frac{TP}{TP+FP}\]

—— 翻译:精确率衡量「模型说『有』的时候,有多少次是真的有」。FP 是「凭空捏造」的幻觉,幻觉越多,precision 越低。

\[recall=\frac{TP}{TP+FN}\]

—— 翻译:召回率衡量「真实存在的物体,模型认出了多少」。FN 是「该看见却漏了」,漏报越多,recall 越低。

精确率和召回率往往此消彼长,于是用它们的调和平均来综合:

\[F1=\frac{2PR}{P+R}\]

—— 翻译:F1 是 precision(P)与 recall(R)的调和平均,只有两者都高它才高;任何一方很低都会把 F1 拽下来,所以它比单看 accuracy 更难被偏科蒙混。

POPE 还设计了三种负样本采样,让任务从易到难:random(随机挑一个图里不存在的物体来问,最简单);popular(专挑数据集里高频出现的物体,模型容易因「常见就猜有」而中招);adversarial(专挑那些和图中物体高频共现的物体——比如图里有桌子就问「有没有椅子」,最难,直击模型的共现先验)。同一个模型在三种采样下分数依次下降,adversarial 最能照出真本事。

MMStar 则换了个角度量化「视觉到底有没有用」。它的核心思想是对比同一道题在给图和不给图两种条件下的准确率:如果不给图也能答对,说明这道题视觉不必要(视觉冗余);如果不给图准确率骤降,说明视觉是不可或缺的。MMStar 据此人工精选出 1500 道「视觉不可或缺(vision-indispensable)」的题,并提出两个度量:一是视觉必要性(给图与不给图的准确率之差,差越大说明越依赖视觉),二是数据泄漏度(若模型在不给图、甚至完全没见过该图的情况下都答得异常好,就高度怀疑训练数据里混进了测试题)。

5.5 洞察

  • 榜单高分要打折看。 视觉冗余 + 数据泄漏意味着:一个 MMMU/MMBench 上的漂亮分数,可能有相当一部分来自「不看图也能蒙」或「背过题」,而非真实的视觉理解。看到一个高分,先问一句——这分里有多少是视觉真的在出力?
  • 数据泄漏(contamination)是评测的头号毒药。 一旦测试题混进了训练数据,benchmark 就从「考试」退化成「默写背过的答案」,分数彻底失去区分力,还会误导后续所有横向对比。这也是为什么 MMStar 要专门量化泄漏度。
  • 「打假」指标自有其价值。 选用 vision-indispensable 子集(如 MMStar 1500 题)、用 POPE-F1 这类专门抓幻觉的指标,才能把「真看懂」从「会蒙」里筛出来。这些反向指标不进厂商发布会的头版,却是判断模型是否可靠的试金石——这一类陷阱(污染、泄漏、格式敏感)会在 §8 做系统的总收束。

6. Grounding 定位:RefCOCO / LVIS / ScreenSpot / PixMo-Points

前面几节(§1–§5)的北极星指标——MMMU 的 accuracy、DocVQA 的 hit、POPE 的 F1——都建立在同一个前提上:模型给出一段文字,我们判断这段文字答得对不对。本节开始,评测发生一次范式切换:我们不再问「你说对了吗」,而是问「你指对地方了吗」。北极星也随之换脸——这一层看的是 RefCOCO Acc@0.5 和 ScreenSpot 命中率。这一层和「双向多粒度 grounding」这类前沿方向直接相关,可以说是它的主场。

6.1 直觉

设想三种新任务。第一种:给一张街景图和一句话「最左边那个穿红衣服的人」,模型要画一个框把那个人圈出来——这就是 RefCOCO 这一类 referring expression grounding。第二种:给一张软件界面截图和一句指令「打开设置」,模型要点中那个设置按钮——这就是 ScreenSpot 类 GUI 定位。第三种:给一张图和「图里有几只羊」,模型用点坐标逐个戳出每只羊——这就是 Molmo 的 PixMo-Points pointing。

怎么判这种题对不对?文字题可以做字符串比对,位置题不行。核心直觉只有两条:

  • 框得准 = 框和答案重叠多少。 模型画的框和标准答案框,如果几乎完全重合,就是准;如果只蹭到一个角,就是不准。衡量「重合多少」的尺子叫 IoU(交并比):两个框重叠区域占它们并起来总面积的比例。IoU 越接近 1 越准。RefCOCO 约定 IoU ≥ 0.5 就算「指对了」。
  • 点得准 = 点有没有落进目标里。 GUI 定位和 pointing 输出的是一个坐标点,不是框。判定更简单粗暴:这个点落在目标元素的框内,就命中;落在框外,就没中。ScreenSpot 的命中率就是这么数出来的。

一句话:这一层把「答案」从一段文字变成了几何对象(框或点),把「判对」从文本比对变成了几何重叠判定。

6.2 最小 demo

先手写一个 IoU 函数,再用 0.5 阈值判命中,跑几个例子建立手感。

def iou(a, b):
    # 框用 [x1, y1, x2, y2] 表示(左上角、右下角)
    ix1, iy1 = max(a[0], b[0]), max(a[1], b[1])   # 交集左上角
    ix2, iy2 = min(a[2], b[2]), min(a[3], b[3])   # 交集右下角
    inter = max(0, ix2 - ix1) * max(0, iy2 - iy1) # 交集面积(不重叠则为 0)
    area_a = (a[2] - a[0]) * (a[3] - a[1])
    area_b = (b[2] - b[0]) * (b[3] - b[1])
    union = area_a + area_b - inter               # 并集 = 两框之和 - 交集
    return inter / union if union > 0 else 0.0

gt = [10, 10, 50, 50]                  # 标准答案框
preds = [[12, 12, 52, 52],             # 几乎重合 → 高 IoU
         [30, 30, 70, 70],             # 只蹭一半 → 中等 IoU
         [80, 80, 100, 100]]           # 完全不沾边 → IoU = 0

hits = 0
for p in preds:
    score = iou(gt, p)
    hit = score >= 0.5                 # RefCOCO 的命中判定
    hits += hit
    print(f"pred={p}  IoU={score:.3f}  命中={hit}")

print(f"Acc@0.5 = {hits / len(preds):.3f}")  # 命中均值

运行后第一个框 IoU 约 0.81(命中),第二个约 0.39(未命中),第三个为 0(未命中),Acc@0.5 = 0.333。可以看到 RefCOCO 的打分本质就是两步:每条样本算一个 IoU,再用阈值把它压成 0/1,最后求均值。把阈值调高到 0.75,第一个框还能过,整体就会更严。

6.3 正式化

IoU(交并比)。 给定预测框 \(A\) 与标准框 \(B\):

\[IoU = \frac{|A \cap B|}{|A \cup B|}\]

—— 翻译:两个框相交的面积,除以它们合起来覆盖的总面积;完全重合得 1,毫无重叠得 0,是衡量「框得多准」的连续尺子。

RefCOCO Acc@0.5。 设第 \(i\) 条样本的最佳预测框与标准框的交并比为 \(IoU_i\),阈值 \(\tau = 0.5\),全集 \(N\) 条:

\[\text{Acc@}\tau = \frac{1}{N}\sum_{i=1}^{N}\mathbb{1}\!\left[IoU_i \ge \tau\right]\]

—— 翻译:逐条样本判断「IoU 是否达到阈值」,达到记 1、不达记 0,再求平均;Acc@0.5 就是「IoU 至少 0.5 的样本占比」,这正是 RefCOCO / RefCOCO+ / RefCOCOg 发布时的北极星。

检测 AP / mAP(LVIS)。 LVIS 是上千类的长尾检测数据集,类别分布极不均,不能只数命中率,而要兼顾「找全」(recall)与「找准」(precision)。其思想是:按某个 IoU 阈值把预测判为 TP/FP,沿置信度从高到低扫描,画出 precision-recall 曲线,取曲线下面积作为某一类的 AP,再对所有类求平均得 mAP。形式上某类的 AP 可写作:

\[AP = \int_{0}^{1} p(r)\, dr, \qquad mAP = \frac{1}{C}\sum_{c=1}^{C} AP_c\]

—— 翻译:\(p(r)\) 是召回率为 \(r\) 时的精确率,积分即 PR 曲线下面积(单类的综合得分);对 \(C\) 个类别的 AP 求平均得到 mAP,长尾数据里这样才不会被头部大类掩盖尾部小类。

ScreenSpot 点命中。 GUI 定位输出一个坐标点 \(\hat{p}=(\hat{x},\hat{y})\),目标元素框为 \(B=[x_1,y_1,x_2,y_2]\),命中当且仅当点落入框内:

\[\text{hit} = \mathbb{1}\!\left[x_1 \le \hat{x} \le x_2 \;\wedge\; y_1 \le \hat{y} \le y_2\right]\]

—— 翻译:预测点的横纵坐标都落在目标框的左右、上下边界之间就算命中;ScreenSpot / ScreenSpot-Pro 的命中率就是所有指令上 hit 的均值。PixMo-Points 的 pointing 评测同理,只是目标从界面元素换成图中物体。

def compute_iou(box1, box2):
    """Compute Intersection over Union (IoU) of two bounding boxes."""
    if box1 == [0, 0, 0, 0]:
        return 1 if box2 == [0, 0, 0, 0] else 0

    x_left = max(box1[0], box2[0])
    y_top = max(box1[1], box2[1])
    x_right = min(box1[2], box2[2])
    y_bottom = min(box1[3], box2[3])

    intersection = max(0, x_right - x_left) * max(0, y_bottom - y_top)
    area1 = (box1[2] - box1[0]) * (box1[3] - box1[1])
    area2 = (box2[2] - box2[0]) * (box2[3] - box2[1])
    union = area1 + area2 - intersection

    return intersection / union if union > 0 else 0

对照:x_left/y_top/x_right/y_bottom 算的就是交集矩形的左上、右下角,intersection 即 \(|A\cap B|\),union = area1 + area2 - intersection 即 \(|A\cup B|\),最后一行就是 \(IoU=\frac{|A\cap B|}{|A\cup B|}\)。开头对 [0,0,0,0] 的特判处理「标准答案本就是空框」的退化情形——和我们 demo 里手写的逻辑一模一样,只是更鲁棒。

6.5 洞察

  • box→mask,指标随之升级。 本节判的是框和点,衡量尺子是 IoU 和点命中率。当任务从「框出物体」细到「逐像素抠出物体轮廓」(分割),IoU 就升级为 mIoU(对每个目标算掩码 IoU 再求平均)——这正是下一节 §7 在像素级细节/瑕疵定位里要接手的指标,本节的几何直觉会被原样复用。
  • 这一层的北极星是 RefCOCO Acc@0.5 与 ScreenSpot 命中率。 厂商发布带 grounding / GUI agent 能力的模型时,头版往往摆这两个数;读榜时要分清它报的是 Acc@0.5(宽松)还是更高阈值(严格)。仓库内更细的 grounding benchmark 盘点详见教程《VLM Grounding 全景》§8(../vlm-grounding-2025/);PixMo-Points 的 pointing 范式细节见 Molmo 精读(../../papers/molmo-2024/)。
  • 这一层只是「指对位置」的正向一半。 RefCOCO / ScreenSpot / PixMo 测的都是正向:给一句话,输出位置。但完整的「双向 grounding」还有反向的一半——给一个位置,生成对它的描述——以及跨粒度(框/点/掩码)的统一评测。这些是现有 benchmark 没有覆盖、需要研究者自建的部分(呼应 §8 的「缺口即自建信号」)。

7. 细节 / 瑕疵:MVTec-AD / VisA / QGround

7.1 直觉

前面 §1–§6 的整套尺子,底层都是「答对没有」——把模型的回答和标准答案比一比,对了记一分,这就是 accuracy 体系。可是一旦走进找瑕疵这一层,这把尺子突然不灵了。

想象工厂质检:一条产线上 99.9% 的产品是好的,真正的缺陷又小又罕见。如果还用「对/错分类」,模型只要永远说「没缺陷」,准确率就接近 100%——分数高得离谱,却毫无用处。所以这个社区换了一套完全不同的评分哲学:不看「判得对不对」,而看「异常分数排得好不好」。

打个比方,这更像体检报告里的风险排序,而不是一刀切的「健康/不健康」。医生不会武断地给你贴标签,而是把所有人按风险高低排个队,真正高危的排在前面。衡量这种「排序质量」的指标就是 AUROC:只要所有异常样本的分数都比正常样本高,排序就完美(AUROC = 1.0);完全乱排则等于瞎猜(0.5)。它和阈值无关,因此回避了「99.9% 正常」带来的偏差。

到了像素级,问题升级为「缺陷在图上哪个位置」。这时把每个像素当作一个待排序的样本,算 pixel-AUROC;或者用 PRO(Per-Region Overlap),对每块缺陷区域单独计覆盖率,避免大缺陷淹没小缺陷。而画质失真这类任务(QGround)又回到分割,沿用 §6 的 IoU 思路,用 mIoU 评分。

关键反差有两点。其一,这套 AUROC / pixel-AUROC / PRO / mIoU 指标和 §1–§6 的 accuracy 体系根本不兼容——一边是「答对计分」,一边是「排序面积」,没法放进同一张榜单横比。其二,在 MVTec-AD、VisA 这些黄金基准上刷分的,大多还不是 VLM,而是工业界专门设计的异常检测模型(只学正常样本、推理时找偏离)。这一层离「双向多粒度 grounding」这类前沿方向的细节粒度最近,却也最难被现有 VLM 范式收编。

7.2 最小 demo

AUROC 听起来玄乎,其实就是「按异常分数排序后,异常样本排在正常样本前面的比例」。下面给每张图一个异常分和真实标签(1 = 异常,0 = 正常),用最朴素的「逐对比较」算 image-AUROC,再和 sklearn 对照:

scores = [0.1, 0.4, 0.35, 0.8, 0.2, 0.9]   # 模型给每张图的异常分
labels = [0,   0,   1,    1,   0,   1]       # 1=真异常, 0=正常

# AUROC = 随机取一个异常样本、一个正常样本，异常分更高的概率
pos = [s for s, y in zip(scores, labels) if y == 1]   # 异常分
neg = [s for s, y in zip(scores, labels) if y == 0]   # 正常分

wins = 0.0
for p in pos:
    for n in neg:
        if p > n:
            wins += 1          # 异常排在正常前面，赢一分
        elif p == n:
            wins += 0.5        # 平手算半分
auroc = wins / (len(pos) * len(neg))
print(f"toy image-AUROC = {auroc:.3f}")      # 0.889

from sklearn.metrics import roc_auc_score
print(f"sklearn AUROC   = {roc_auc_score(labels, scores):.3f}")  # 0.889

两者完全一致。这个「逐对比较」的视角揭穿了 AUROC 的本质:它就是异常分大于正常分的概率,根本不需要选阈值。注意全程没有「预测对错」这回事——分数本身从不被判对错,只被拿来排序。

7.3 正式化

ROC 曲线建立在两个随阈值变化的量上。给定阈值 \(t\),预测为「异常」当且仅当分数 \(s \gt t\),于是:

\[\mathrm{TPR}(t)=\frac{TP(t)}{TP(t)+FN(t)},\qquad \mathrm{FPR}(t)=\frac{FP(t)}{FP(t)+TN(t)}\]

—— 翻译:TPR 是真异常里被抓出来的比例(查全),FPR 是正常样本里被误报的比例(误杀)。阈值 \(t\) 从高到低滑动,两者各自从 0 爬到 1。

把每个阈值对应的点 \((\mathrm{FPR},\mathrm{TPR})\) 连成曲线,曲线下面积即 AUROC:

\[\mathrm{AUROC}=\int_0^1 \mathrm{TPR}\,\mathrm{d}(\mathrm{FPR})\]

—— 翻译:对所有可能的误报率积分查全率;面积越接近 1,说明在任意误报水平下都能抓到更多异常,0.5 等于随机瞎猜。

pixel-AUROC 不改公式,只换样本粒度:把整张测试集里每一个像素当成一个独立样本,用模型输出的「该像素异常分」和「该像素是否落在缺陷掩码内」算同一个 AUROC,从而衡量缺陷定位质量。

PRO(Per-Region Overlap)针对像素级 AUROC 被大缺陷主导的毛病。设真值掩码由若干连通缺陷区域 \(\{R_1,\dots,R_K\}\) 组成,在某阈值下的预测异常区域为 \(P\),则:

\[\mathrm{PRO}=\frac{1}{K}\sum_{k=1}^{K}\frac{\lvert P\cap R_k\rvert}{\lvert R_k\rvert}\]

—— 翻译:对每块缺陷单独算「被预测覆盖的比例」再求平均;一块巨大缺陷和一块微小缺陷权重相同,小缺陷因此不会被忽略。

QGround 的画质失真分割则直接沿用 §6 的 IoU,推广到分割掩码上用 mIoU(各失真类别 IoU 的平均),衡量「失真区域圈得准不准」。

7.5 洞察

  • 指标体系天然排斥 VLM 范式。这一层的评分要么是纯排序(AUROC / pixel-AUROC / PRO),要么是纯分割(mIoU),既没有对话、也没有自然语言答案可判——而 §1–§6 的 VLM benchmark 全靠「从文本里抠出答案再比对」。一个只会输出文字的 VLM,根本接不上「给每个像素一个异常分」这种接口。如何把这种细节粒度统一进 VLM 的语言输出,正是「双向多粒度 grounding」方向要啃的硬骨头。
  • 非 VLM 专用模型在这层抢跑。MVTec-AD(15 类,训练只给正常样本)、VisA(12 类、10,821 张高分辨率图)这些黄金基准的高分,几乎都被工业界专门设计的异常检测模型拿走——它们「只学正常、推理找偏离」的范式天然契合 AUROC,通用 VLM 在这里暂时不占优。
  • 像素 / mask 标注成本极高。pixel-AUROC、PRO、mIoU 都依赖逐像素真值掩码,而画一张缺陷掩码远比写一个选择题答案昂贵,这直接限制了细节级数据集的规模与覆盖面,也是把这层能力规模化进 VLM 的现实瓶颈。

工业异常这条线的指标全貌与实操,详见教程《VLM 工业质检》(../vlm-industrial-2024/);画质失真分割 QGround 的方法与 QGround-100K 数据集,可参阅 Q-Ground 精读,它把失真分割从纯指标推向了「VLM + 分割」的融合尝试,正是本层与主流 VLM 接轨的一个早期样本。

8. 各家北极星对照、怎么读 leaderboard,以及什么时候得自建

8.1 直觉

走到这里,你已经见过五大指标族:命中均值(accuracy)、relaxed accuracy / ANLS、F1、IoU / Acc@0.5 / AP / 点命中率,以及 AUROC / pixel-AUROC / PRO / mIoU。每一族背后都有一个被厂商挑出来「上海报」的那个数——这就是 §1 说的北极星。

现在假设你打开任意一张 OpenVLM Leaderboard,密密麻麻几十列分数。正确的读法不是先看谁第一,而是先问三件事:这一列在测什么能力?它用的是哪个指标(量纲是百分制还是 2800 制)?这个分数会不会是「虚高」出来的?第三个问题最要命,因为榜单上最漂亮的那个数,往往恰恰是被某种陷阱放大的。

把全文压成一张矩阵,就是下面这张图:横轴是「能力层 → 测什么 → 指标 → 北极星」,旁边挂着读榜必须警惕的三大陷阱。

记住一句话:任何单一数字都不可信,你要看的是一整组数字的「形状」。 一个文档模型 DocVQA 95 分但 POPE-F1 只有 70,说明它会读字却爱瞎编;一个模型 MMMU 很高但 MMStar 上「盖住图也能答对」的比例很大,说明它的高分有水分。

8.2 最小 demo

把多个 benchmark 分数汇总成一个排名,听起来只是「加起来除以个数」,但这里藏着 §3 的教训:MME 是 2800 制,MMMU 是百分制,直接相加等于让 MME 一票否决其他所有维度。所以必须先归一化到同一量纲。

# 玩具版 leaderboard 汇总:务必先归一化,再加权
models = {
    "Model-A": {"MMMU": 58.0, "DocVQA": 90.1, "MME": 2050.0, "POPE_F1": 86.0},
    "Model-B": {"MMMU": 61.0, "DocVQA": 84.0, "MME": 1900.0, "POPE_F1": 79.0},
}
# 每个 benchmark 的理论满分(量纲),用来归一化到 [0,1]
full_marks = {"MMMU": 100.0, "DocVQA": 100.0, "MME": 2800.0, "POPE_F1": 100.0}
weights    = {"MMMU": 0.4, "DocVQA": 0.3, "MME": 0.1, "POPE_F1": 0.2}

def aggregate(scores):
    total = 0.0
    for bench, raw in scores.items():
        norm = raw / full_marks[bench]      # 关键:2800 制不能直接和百分制相加
        total += weights[bench] * norm
    return round(total * 100, 2)            # 折回 0-100 便于阅读

ranking = sorted(models.items(), key=lambda kv: aggregate(kv[1]), reverse=True)
for name, scores in ranking:
    print(f"{name}: {aggregate(scores)}  细分={scores}")
# Model-A: 80.6  ...
# Model-B: 78.5  ...

去掉 norm = raw / full_marks[bench] 这一行,MME 的 2050 会把加权和彻底带偏,Model-A 直接「赢」在它根本没多强的维度上。归一化是把不同尺子换算成同一把尺的最低门槛——这也是为什么严肃榜单从不简单地「求和」。

三大陷阱的形式化。第一,视觉冗余——一个题真正需要看图的程度可以定义为:

\[\text{VisualNecessity} = \text{acc}_{\text{有图}} - \text{acc}_{\text{无图}}\]

—— 翻译:把图盖住后模型还能答对多少,差值越小说明这道题越「不看图也能蒙」,§5 的 MMStar 正是靠筛掉这类题来还原真实视觉能力。

第二,数据污染 / 泄漏。设测试集与训练语料的重叠比例为 \(r\),污染会让观测到的分数虚高:

\[\text{acc}_{\text{观测}} = (1-r)\cdot \text{acc}_{\text{真实}} + r\cdot \text{acc}_{\text{背答案}},\quad \text{acc}_{\text{背答案}} \gt \text{acc}_{\text{真实}}\]

—— 翻译:只要有一部分测试题被模型「背过」,加权平均就会高于它的真实泛化能力,\(r\) 越大水分越大,这就是 MMStar 强调要清洗泄漏题的原因。

第三,格式敏感 / 答案提取误差。同一个模型在两套 harness 下的分数满足 \(\text{score}_{A} \neq \text{score}_{B}\),差异来自答案提取器与协议不同(§2)。结论:不同 harness 跑出来的分数不可直接横比,跨榜比较前必须确认是同一套评测协议。

8.5 洞察 + 给小白的 checklist

  • 没有任何单一指标可信,要看一整组。 北极星是营销与真实能力的混合体;真正的诊断来自把同一模型在通用 / 文档 / 幻觉 / 定位多族指标上的分数摆成一行,看它的「形状」哪里塌陷。
  • 量纲不统一时,先归一化再比较。 2800 制的 MME 不能和百分制相加;不同 harness 的分数因答案提取与协议不同也不能直接横比——跨榜比较前永远先确认协议一致。
  • 前沿能力常常没有公开 benchmark,需要自建。 现成榜单覆盖的是已经成熟、被反复刷过的能力。如果你在做双向 grounding、多粒度定位、few-shot pointing 这类前沿方向,会发现几乎找不到现成、对口的公开评测——这类能力目前没有公开 benchmark,前沿团队往往需要自建评测来量化进展,而自建时同样要复用本文这套「数据 / 任务格式 / 指标 / 协议」四要素,并主动设计去污染、查视觉必要性的子集。

小白实操 checklist——拿到一个模型 / 一张榜该怎么核验:

  1. 认能力层:先把每列归到「通用 / 文档 / 数学 / 幻觉 / 定位 / 细节」哪一层,别把不同能力当成一个总分。
  2. 认指标与量纲:这列是 accuracy、ANLS、F1、IoU 还是 AUROC?满分是 100 还是 2800?量纲不同先归一化。
  3. 认协议:是哪套 harness、哪个答案提取器跑的?不同协议的分数不可直接比。
  4. 查视觉冗余:有没有「盖住图也能答对」的对照(如 MMStar 子集)?没有就对纯文本可蒙的高分打个折。
  5. 查污染 / 泄漏:测试集是否可能进过训练语料?越新、越冷门的 benchmark 越可信。
  6. 看一整组而非一个数:对比北极星之外的诚实(POPE-F1)、定位(Acc@0.5)等维度,找塌陷点。
  7. 缺口即自建信号:如果你关心的能力在所有公开榜上都没有对口列,这本身就是要自建 benchmark 的信号——而怎么建,正是前面七节给你的全部工具。
